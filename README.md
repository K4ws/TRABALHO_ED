# ED_Trabalho

Repositório de exercícios desenvolvidos ao longo do período 2026.2 na
disciplina **MAE014 - Tóp. Ciência Dados B [Turmas MAP e EMA]**.

## Organização do repositório

Cada trabalho/exercício da disciplina possui sua própria pasta na raiz deste
repositório (ex.: `classe_pilha/`, `classe_pilha_preenchimento/`,
`classe_pilha_torre_hanoi/`), contendo de forma independente todo o código,
os testes e os relatórios exigidos para aquela entrega.

## Diretrizes padrão de entrega

As regras abaixo valem para **todos** os trabalhos do repositório. As
instruções completas e detalhadas estão em [`AGENT.md`](AGENT.md); este é um
resumo.

Além do código-fonte e dos testes, cada pasta de trabalho deve conter os
seguintes relatórios:

- **`POST_MORTEM.md`** — documento principal de avaliação de autoria, com log
  de iteração e prompts (prompts-chave + código bruto gerado pela IA antes de
  qualquer modificação manual), code review crítico, justificativa de
  refatoração e evidência de testes.
- **`CODE_REVIEW.md`** — revisão crítica do código gerado pela IA, apontando
  onde ela gerou código ineficiente (complexidade de algoritmo, vazamentos de
  memória, falta de índices, problemas de concorrência, etc.).
- **`RELATORIO_TESTES.md`** — bateria de testes (incluindo testes de
  estresse) executados em busca de problemas, mostrando que a versão
  refatorada supera a versão ingênua gerada pela IA.
- **`ANALISE_CRITICA.md`** — análise crítica do uso da IA: o que ela ajudou a
  produzir e o que precisou de revisão humana.
- **`ENTREGA.md`** (recomendado) — checklist de entrega da pasta.

Os quatro relatórios (excluindo os arquivos de código) devem ter também uma
versão em **PDF**, iniciada por uma **folha de rosto** com o nome da
disciplina, o nome do trabalho e o nome completo + DRE de cada integrante do
grupo.

Consulte o [`AGENT.md`](AGENT.md) para a estrutura de pastas esperada, o
detalhamento do conteúdo obrigatório de cada relatório e o processo a seguir
sempre que um novo trabalho for iniciado.
